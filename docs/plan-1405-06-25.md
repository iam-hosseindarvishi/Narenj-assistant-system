## ۲. ماژول جدید «اطلاعات پایه فروش»

### ۲.۱. دکمه در داشبورد اصلی
- کارت در ردیف عملیات — همین سبک کارت مغایرت‌گیری؛ نمایان فقط برای admin و دارای مجوز `sales_base`

### ۲.۲. داشبورد ماژول
- صفحه اصلی با کارت‌های گزارش (placeholder «جلوتر پیاده‌سازی می‌شود»)
- `SalesBaseLayout.vue` با سایدبار — همان زبان بصری `AdminLayout.vue` + «← داشبورد اصلی»
- مسیرها: `/sales-base/...` با گارد `meta: { module: 'sales_base' }`

### ۲.۳. سایدبار

**ویزیتور:**
- لیست ویزیتورها (CRUD) / مسیرهای فروش (CRUD)
- برنامه هفتگی: برای هر ویزیتور، هر روز هفته (شنبه–جمعه)، کدام مسیرها ویزیت شود؛ چند مسیر در یک روز مجاز
- ارتباط مشتری با ویزیتور: چند‌به‌چند با نقش مسیر (ویزیتور↔چند مشتری/مسیر، مشتری↔چند ویزیتور، مسیر↔۲-۳ ویزیتور)

**مشتریان:**
- لیست مشتریان (CRUD) / مسیرهای مشتریان (فقط نسبت‌دادن مسیر ویزیت)
- درج گروهی از اکسل — بعداً (دکمه غیرفعال «به‌زودی»)

**گروه کالا:**
- لیست گروه کالا (CRUD + ثبت از اکسل با خط لوله آپلود/کلیپ‌بورد مغایرت‌گیری)
- قواعد فروش: (ویزیتور، مسیر، گروه) — پیش‌فرض فروش همه گروه‌ها آزاد است؛ با ثبت قاعده، گروه در آن مسیر به آن ویزیتور اختصاص می‌یابد

**گزارش تخلفات:**
- ورود فروش بعداً از مسیر دیگر؛ این صفحه موتور و UI گزارش است
- قانون: اگر ویزیتور X در مسیر R گروه G را بفروشد و قاعده (Y≠X، R، G) ثبت شده باشد → تخلف با ذکر ویزیتور مالک؛ بدون قاعده برای (R,G) → تخلف نیست
- بازه هفتگی شنبه–جمعه، تقویم جلالی، انتخاب هفته

### ۲.۴. مدل داده (PostgreSQL)
- `visitors` / `sales_routes` / `weekly_program` (یونیک visitor+day+route)
- `customers` / `customer_routes` / `customer_visitor_links` (چند‌به‌چند)
- `product_groups` / `group_rules` (یونیک visitor+route+group)
- `sales` (جدول و موتور تخلف از الان ساخته می‌شود؛ ورودی بعداً وصل می‌شود)
- تقویم: `app/services/jalali.py` موجود؛ مرز هفته شنبه ۰۰:۰۰ تا جمعه ۲۳:۵۹

### ۲.۵. بک‌اند
- روتر `app/routers/sales_base.py`: CRUD همه موجودیت‌ها + قواعد + `GET /api/sales-base/violations?week=...`

- تست pytest: CRUD + موتور تخلف (قاعده‌دار/بدون قاعده/قاعده خود ویزیتور)
